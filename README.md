# منظومة «أمبيرجي» لإدارة المولدات الأهلية والجباية الميدانية (PWA)

تطبيق ويب تقدمي إنتاجي متكامل (**Offline-First Progressive Web App**)، مصمم خصيصاً لأصحاب ومتعهدي المولدات الأهلية في العراق. يعمل بعد التثبيت كتطبيق أصلي مستقل تماماً، ويعتمد على محرك **SQLite WebAssembly** والتخزين الدائم **OPFS** (Origin Private File System) بنسبة 100% بدون أي خوادم أو شبكات CDN خارجية.

---

## ⚡ المزايا والخصائص التقنية

1. **معمارية خالية تماماً من الـ CDN (Zero-CDN Architecture):**
   - كافة الخطوط العربية (Cairo woff2)، مكتبات التشفير، ومحرك `sqlite3.wasm` مدمجة محلياً داخل حزمة البناء.
   - لا يتم إرسال أي طلب شبكة خارجي وقت التشغيل على الإطلاق.
2. **قاعدة بيانات SQLite WASM + OPFS:**
   - تخزين دائم فائق السرعة عبر Web Worker مستقل.
   - حماية كاملة من المسح التلقائي على أجهزة iOS/Safari بفضل عزل بيئة الـ Standalone.
   - وضع تجربة مؤقت للذاكرة (:memory:) عند الفتح من متصفح الويب العادي لتنبيه المستخدم.
3. **نظام تراخيص رقمي مشفر (100% Offline Licensing):**
   - يعتمد على تشفير المفتاح العام/الخاص (ECDSA P-256 + SHA-256).
   - المفتاح الخاص **لا يُضمَّن أبداً** في التطبيق أو حزمة الويب؛ تُصدر الأكواد عبر أداة CLI محلية ثم تُلصق في لوحة الإدارة.
   - تجربة مجانية كاملة لمدة 30 يوماً من أول تشغيل.
   - بعد انتهاء الـ 30 يوماً: قفل إضافة مشتركين أو وصولات جديدة فقط، مع إبقاء استعراض السجلات، طباعة الوصولات، وتصدير التقارير متاحاً دائماً للمستخدم بدون فقدان أي بيانات.
4. **وصل قبض حراري ميداني (Thermal Invoicing 58mm/80mm):**
   - تنسيق طباعة حرارية دقيق متوافق مع طابعات البلوتوث المحمولة، يدعم المشاركة والطباعة الفورية.
5. **نسخ احتياطي واستعادة آمنة:**
   - لقطات تلقائية داخل مساحة OPFS كل 50 تعديلاً (حفظ آخر 7 نسخ تدويرية).
   - تصدير واستيراد قواعد بيانات SQLite مع فحص سلامة الجداول `PRAGMA integrity_check`.
   - تصدير كشوفات الحسابات والمشتركين إلى جداول CSV / Excel.
6. **واجهة عربية أصيلة (RTL Mobile-First):**
   - تصميم فائق الخفة والسرعة بـ **Vanilla TypeScript** بدون أي أطر عمل ثقيلة.
   - وضع النهار فائق التباين (Sunlight High Contrast Mode) للقراءة تحت أشعة الشمس المباشرة أثناء الجباية الميدانية.
7. **منصة SaaS متكاملة ولوحة تحكم مدير المنصة (Super Admin Dashboard):**
   - تسجيل فوري لأصحاب المولدات في العراق (Onboarding) مع تفعيل تلقائي لشهر تجريبي مجاني.
   - لوحة تحكم مركزية لصاحب المنصة لمراقبة كافة المولدات، إجمالي المشتركين التراكمي، وحالة الاشتراكات.
   - تفعيل شهري (+30 يوم) وسنوي (+365 يوم)، وتطبيق أكواد التراخيص الموقعة الصادرة من أداة CLI.
   - عزل كامل لبيانات كل مولدة (Tenant Isolation) في المشتركين والجباية والمصاريف والتقارير.
   - الدخول كمعاينة لأي مولدة لتقديم الدعم الفني، والتواصل المباشر عبر واتساب.

## 🛡️ الدخول إلى لوحة الإدارة (Super Admin)

لوحة الإدارة **ليست ظاهرة** كزر في واجهة المستخدم العادية. الوصول إليها عبر مسار مستقل:

| الطريقة | المسار |
| --- | --- |
| فتح لوحة الإدارة مباشرة | `https://<نطاق-التطبيق>/#admin` |
| أو | `https://<نطاق-التطبيق>/#login` |

بيانات الدخول الافتراضية عند أول تثبيت:

- **اسم المستخدم:** `admin`
- **كلمة المرور:** `power`

> ⚠️ **مهم جداً:** غيّر كلمة المرور فور أول دخول من زر **«🔐 كلمة المرور»** داخل اللوحة. كلمات المرور تُخزَّن مشفرة عبر PBKDF2-SHA256 (210,000 دورة) مع Salt عشوائي، وتُقفل المحاولات مؤقتاً بعد 5 محاولات خاطئة. الجلسة صالحة لمدة 8 ساعات وتُحفظ في `sessionStorage` وتنتهي بإغلاق التبويب.

عند وجود جلسة إدارة نشطة يظهر زر **«🛡️ العودة للإدارة»** في الهيدر للتنقل السريع، ولا يظهر أبداً للمستخدم العادي.

## 🚀 التشغيل والتطوير المحلي

### متطلبات التشغيل
- Node.js (الإصدار 18 فما فوق).
- مدير الحزم npm أو pnpm.

### 1. تثبيت الحزم
```bash
npm install
```

### 2. تشغيل خادم التطوير
```bash
npm run dev
```
> **ملاحظة:** يتم توليد شهادة SSL محلية تلقائياً (`basicSsl`) لتمكين ترويسات العزل `Cross-Origin-Opener-Policy` و`Cross-Origin-Embedder-Policy` الضرورية لـ SQLite OPFS.

### 3. بناء واختبار حزمة الإنتاج
لاختبار الـ Service Worker وحزمة الـ PWA الإنتاجية محلياً:
```bash
npm run build
npm run preview
```

## 🌐 النشر والاستضافة

### الخيار الأول: النشر على Vercel (موصى به)
ملف `vercel.json` جاهز ومضبوط مسبقاً بترويسات الأمان وعزل النطاقات وإعدادات الكاش الصحيحة:
1. اربط مستودع GitHub بحسابك على [Vercel](https://vercel.com).
2. إعدادات المشروع:
   - **Framework Preset:** Vite
   - **Build Command:** `npm run build`
   - **Output Directory:** `dist`
3. اضغط **Deploy**. سيعمل التطبيق مباشرة بدعم HTTPS وترويسات COOP/COEP كاملة.

### الخيار الثاني: النشر على استضافة خاصة (Apache)
ملف `public/.htaccess` مدمج داخل حزمة البناء. تأكد من تفعيل الموديلات التالية في Apache:
```apache
a2enmod rewrite
a2enmod headers
a2enmod mime
```
وتأكد من تفعيل HTTPS الإلزامي لميزات PWA وOPFS.

### الخيار الثالث: النشر عبر Nginx
استخدم النموذج الجاهز في ملف `nginx.conf.example`:
```nginx
# ترويسات العزل الإلزامية لـ SQLite OPFS
add_header Cross-Origin-Opener-Policy "same-origin" always;
add_header Cross-Origin-Embedder-Policy "require-corp" always;
```

## 🔐 نظام إدارة التراخيص الرقمية (Licensing CLI)

يحتوي مجلد `tools/` على سكربت Node.js مستقل لإصدار مفاتيح التفعيل الموقعة رقمياً دون أي اتصال بالإنترنت.

### 1. توليد زوج المفاتيح (يُنفذ مرة واحدة فقط):
```bash
npm run license:keys
# أو: node tools/generate-license.js generate-keys
```
سيتم حفظ المفاتيح في `tools/license-keys.json`. هذا الملف **سري** ومستبعد من Git عبر `.gitignore`، ويجب ألا يُنشر أو يُرفع إلى أي مستودع أو استضافة. بعد التوليد، انسخ المفتاح العام (JWK) وضعه في `src/license/license.ts` (الحقل `PUBLIC_KEY_JWK`).

لعرض المفتاح العام الحالي:
```bash
node tools/generate-license.js show-public
```

### 2. إصدار كود ترخيص لمولدة معينة:
```bash
# ترخيص سنوي (365 يوماً)
node tools/generate-license.js issue --name "مولدة النور الأهلية" --phone "07701234567" --type yearly

# ترخيص شهري (30 يوماً)
node tools/generate-license.js issue --name "مولدة النور الأهلية" --phone "07701234567" --type monthly

# ترخيص دائم
node tools/generate-license.js issue --name "مولدة النور الأهلية" --phone "07701234567" --type lifetime
```
أو عبر npm:
```bash
npm run license:issue -- --name "مولدة النور الأهلية" --phone "07701234567" --type yearly
```

### 3. تفعيل الترخيص في التطبيق:
1. انسخ الكود الناتج (يبدأ بـ `AMPEREJI-...`).
2. افتح لوحة الإدارة `#admin` ← تبويب **إدارة المولدات** ← زر **«🔑 تطبيق كود ترخيص»** بجانب المولدة المطلوبة، أو من شاشة **الإعدادات** للمولدة الحالية.
3. سيتم فحص التوقيع الرقمي فورياً عبر WebCrypto داخل التطبيق، ثم ربط الترخيص بالمولدة وتحديث تاريخ الانتهاء تلقائياً — بدون أي اتصال بالإنترنت.

> **ملاحظة أمنية:** أي تراخيص صادرة بالمفتاح الخاص القديم لن تعمل بعد تدوير المفاتيح. أعد إصدارها بالمفتاح الحالي.

## 💳 (اختياري) ربط نظام التراخيص ببوابات الدفع الإلكتروني

لأتمتة بيع الاشتراكات عبر الإنترنت (ZainCash, Qi Card, Stripe, Lemon Squeezy) مستقبلاً:

```
العميل يدفع عبر بوابة الدفع الإلكتروني
    ⬇️
Webhook من بوابة الدفع إلى دالة سحابية (Vercel Serverless Function)
    ⬇️
الدالة تحتفظ بالمفتاح الخاص في متغيرات البيئة (ENV: PRIVATE_KEY_PEM) — وليس في الويب
    ⬇️
توليد كود الترخيص الموقع رقمياً للمشترك
    ⬇️
عرض كود التفعيل في صفحة إتمام الدفع أو إرساله عبر الرسائل القصيرة SMS / واتساب
```

> التطبيق الحالي Offline-First بالكامل ولا يتصل بأي بوابة دفع. هذا القسم يوضح مسار التكامل الاختياري فقط، مع بقاء المفتاح الخاص خارج المتصفح دائماً.

## 🔒 سياسة الخصوصية والأمان

- **بياناتك على جهازك فقط:** لا يحتوي التطبيق على أي خادم تخزين سحابي، ولا يتم تتبع أي مشترك أو جمع أي بيانات شخصية أو مالية.
- **التشفير الداخلي:** يتم تخزين قاعدة البيانات داخل مساحة التخزين الخاصة للمتصفح (OPFS) التي لا يمكن للمواقع الأخرى أو التطبيقات الخارجية الوصول إليها.
- **مصادقة الإدارة:** كلمات المرور لا تُخزَّن كنص صريح؛ تُستخدم PBKDF2-SHA256 (210,000 دورة) مع Salt عشوائي لكل حساب. جلسة الإدارة مؤقتة في `sessionStorage` وتنتهي بعد 8 ساعات، وتُقفل المحاولات بعد 5 إخفاقات متتالية.
- **عزل المستأجرين:** كل استعلامات المشتركين والجباية والمصاريف والتقارير مقيّدة بـ `tenant_id` للمولدة النشطة، ولا يمكن لمولدة رؤية بيانات مولدة أخرى.
- **المفتاح الخاص:** لا يُضمَّن مفتاح التوقيع الخاص في حزمة الويب إطلاقاً. يُصدر فقط من أداة CLI على جهاز موثوق، وملف المفاتيح مستبعد من Git.
